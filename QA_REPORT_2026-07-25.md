# Continuity Engine QA Report

**Date:** 2026-07-25
**Repository:** amy2213/continuity-engine
**Reviewed baseline:** v0.4.1-alpha
**Scope:** theory-to-code alignment, classifier architecture, datasets, validation framing, revision latency, IRR tooling, rater randomization, known-failure documentation, and research governance.

## Executive assessment

Continuity Engine is a credible research prototype with strong transparency and a clear conceptual contribution. It is not yet a validated measurement instrument.

The principal QA finding is not a conventional software bug. It is a measurement mismatch:

> The human coding rubric and the software classifier do not yet operationalize the eight dimensions in the same way.

The human rubric scores semantic strength and dominance. The software primarily counts distinct matched regex patterns and caps the result at 3.

That mismatch must be addressed before engine-human agreement can be interpreted as evidence about construct validity.

## Current strengths

1. The repository clearly distinguishes internal consistency from external validation.
2. The classifier is transparent and auditable.
3. Known weaknesses are documented instead of hidden.
4. The project includes infrastructure for blinded human coding and inter-rater reliability.
5. The rule cascade encodes meaningful distinctions, especially Boundary vs Defensive, Fragmented vs Overloaded, and Flexible vs Integrated.
6. Ethics language correctly treats classifications as properties of text-processing episodes, not people.

## Severity key

- **P0:** research-integrity or validity blocker
- **P1:** major measurement or correctness issue
- **P2:** important robustness or analysis improvement
- **P3:** cleanup or maintainability improvement

# Findings

## CE-QA-001: Human rubric and software scores are not operationally equivalent

**Severity:** P0

### Finding

The rubric defines 0-3 as absent, weak/implied, clear, and dominant/load-bearing. The engine largely scores by number of distinct regex pattern types detected, capped at three.

### Risk

A future human-vs-engine reliability result could conflate classifier implementation differences with disagreement about the underlying theory.

### Required action

Treat the human construct definitions as authoritative. Maintain an explicit construct-to-machine specification and redesign machine observables rather than simplifying the rubric.

---

## CE-QA-002: Self-Reference Density is not currently density

**Severity:** P1

### Finding

Marker detection records whether each regex pattern appears, not how many times it occurs. Repeated uses of the same first-person marker therefore do not increase the raw marker count.

### Risk

The current implementation measures marker diversity more than density.

### Required action

Count self-reference occurrences and normalize by text length. Validate thresholds against human SR ratings.

---

## CE-QA-003: Semantic dominance is approximated by marker diversity

**Severity:** P1

### Finding

Identity Fixity, Prediction, Threat, Feedback Integration, Narrative Flexibility, Fragmentation, and Updated Continuity can all receive high scores because several distinct regex patterns fire, even if the construct is not load-bearing in the passage.

### Required action

Introduce feature families for frequency, scope, intensity, structural centrality, temporal direction, and resolution status.

---

## CE-QA-004: Cascade order encodes undocumented theoretical precedence

**Severity:** P1

### Finding

The ordered classifier cascade determines which state wins in collision cases. These priorities are therefore part of the model, even where they currently appear only as control flow.

### Required action

Create and maintain a formal state-precedence specification explaining pairwise tie-breaks and collision handling.

---

## CE-QA-005: Confidence is rule clarity, not calibrated confidence

**Severity:** P1

### Finding

High/Medium/Low values are assigned by classification branches. They do not represent observed probability of correctness.

### Risk

Users may interpret High as empirically reliable.

### Required action

Prefer `classification_clarity` terminology until confidence can be calibrated against held-out human-coded data.

---

## CE-QA-006: Negation handling remains a structural weakness

**Severity:** P1

### Finding

Surface pattern matching can detect content inside negated statements.

Example class:

`I am not saying they are incompetent.`

### Required action

Add lightweight negation-scope preprocessing before construct detection.

---

## CE-QA-007: Quoted speech and speaker attribution are structural weaknesses

**Severity:** P1

### Finding

The engine can attribute quoted or reported language to the narrator.

### Required action

Add quotation and speaker-scope handling. Preserve reported prior beliefs separately from current narrator beliefs.

---

## CE-QA-008: Known-weakness set must remain a challenge set

**Severity:** P0 governance

### Finding

The known-weakness corpus is scientifically useful precisely because it contains documented failures.

### Required action

Freeze it. Do not tune repeatedly until it reaches 100 percent and then present the result as validation.

Future changes may be evaluated against it, but evaluation must also use fresh held-out cases.

---

## CE-QA-009: Pilot and adversarial 100 percent results are not generalization evidence

**Severity:** P0 governance

### Finding

The repository already states this correctly.

### Required action

Preserve this framing everywhere the numbers are reported. Prefer terms such as `specification compliance`, `internal consistency`, and `regression stability` rather than generic classifier accuracy when describing those datasets.

---

## CE-QA-010: Revision Latency naming is incorrect

**Severity:** P1

### Finding

`latency_to_flexible` currently returns the position of the first state in the full adaptive set, Flexible or Integrated.

### Required action

Rename conceptually to `latency_to_adaptive`. Retain a separate `latency_to_integrated` metric.

---

## CE-QA-011: Revision latency uses one-based position rather than elapsed transitions

**Severity:** P2

### Finding

The first adaptive unit is numbered 1. This is a sequence position, not necessarily latency.

### Required action

Report both sequence position and elapsed transition count. Define transition latency explicitly.

---

## CE-QA-012: Revision latency can be reported without initial destabilization

**Severity:** P2

### Finding

A sequence can receive an adaptive position even when it did not begin in a destabilized state.

### Required action

Separate general first-adaptive-position metrics from recovery metrics. Recovery latency should require a defined destabilization start.

---

## CE-QA-013: Trajectory score is document-length dependent

**Severity:** P2

### Finding

Trajectory score is the sum of state values. Longer documents naturally produce larger absolute magnitude.

### Required action

Report both raw score and normalized score per narrative unit.

---

## CE-QA-014: Paragraph boundaries are formatting proxies, not validated narrative units

**Severity:** P1 theory/measurement

### Finding

Document analysis splits on newlines and treats paragraphs as the trajectory units.

### Risk

Equivalent reasoning formatted differently can produce different latency structures.

### Required action

Research and define a narrative unit independent of visual formatting. Candidate units include sentence, proposition, self-model assertion, event-response episode, or revision event.

---

## CE-QA-015: IRR calculator accepts unknown state labels

**Severity:** P1

### Finding

Unknown labels are normalized to themselves rather than rejected.

### Required action

Validate all primary and secondary states against allowed values and raise a descriptive error on invalid entries.

---

## CE-QA-016: Invalid dimension values are silently converted to missing values

**Severity:** P1

### Finding

Dimension parse failures become `None`, and agreement calculations can skip them.

### Risk

Bad data can silently improve reported agreement.

### Required action

Reject invalid, missing, or out-of-range dimension scores unless an explicit missing-data protocol is enabled and reported.

---

## CE-QA-017: Common-sample intersection can hide missing coder rows

**Severity:** P1

### Finding

IRR analysis uses the intersection of sample IDs across coders.

### Risk

Missing difficult samples can disappear from analysis without prominent warning.

### Required action

Report expected count, missing IDs per coder, extra IDs per coder, and excluded IDs before computing agreement.

---

## CE-QA-018: Duplicate coder sample IDs can overwrite prior rows

**Severity:** P1

### Finding

Rows are stored in a dictionary by sample ID.

### Required action

Raise an error on duplicate IDs.

---

## CE-QA-019: Ordinal dimension scores need ordinal reliability statistics

**Severity:** P2

### Finding

Exact and within-one agreement are useful but incomplete for 0-3 ordinal scales.

### Required action

Add weighted pairwise kappa and evaluate Krippendorff's alpha for ordinal ratings. Use ICC only if its assumptions are justified.

---

## CE-QA-020: Randomization uses global RNG state

**Severity:** P3

### Required action

Use a local `random.Random(seed)` instance.

---

## CE-QA-021: Randomization may violate maximum streak constraint

**Severity:** P2

### Finding

If no valid candidate is available, the algorithm falls back to the first available state.

### Required action

Either guarantee the constraint algorithmically or explicitly report that the requested arrangement could not be satisfied.

# Theory findings

## T-001: Updated Continuity may be an outcome rather than a peer dimension

**Status:** Research hypothesis

The expanded theory suggests that Updated Continuity may be produced by the interaction of revision pressure, fixity, evidence weighting, revision capacity, revision magnitude, and continuity preservation.

This should be tested rather than immediately implemented.

## T-002: Fragmentation should be defined as unresolved model competition

Contradiction alone is insufficient. The theory should require incompatible self-models that remain simultaneously active without successful adjudication or integration.

## T-003: Defensive and Rigid should be mechanistically distinguished

- Defensive: model preservation through evidence rejection, discounting, externalization, or attack.
- Rigid: prior model dominance that constrains what new evidence is permitted to mean.

## T-004: Overloaded is a revision-process capacity failure

Overload is not merely high threat. It is a state in which coherent revision, meaning-making, planning, or action becomes temporarily unavailable.

## T-005: Transitions may be the stronger unit of analysis

The framework is a process theory. Future validation should examine state transitions and trajectories, not only isolated state labels.

# Validation sequence

## Phase A: Human construct reliability

Test whether independent raters can apply the rubric consistently without using engine outputs.

## Phase B: Construct refinement

Use disagreements to refine definitions and tie-break rules.

## Phase C: Frozen human gold set

Create a held-out corpus that has never been used for rule development. Freeze consensus labels before running the engine.

## Phase D: Engine evaluation

Report:
- confusion matrix
- macro F1
- balanced accuracy
- per-state precision
- per-state recall
- rule-clarity calibration

## Phase E: Ablation

Remove individual architectural components to determine which components materially improve performance.

## Phase F: Cross-domain evaluation

Evaluate domains separately before aggregating results.

Candidate domains:
- reflective writing
- workplace conflict
- recovery narratives
- essays
- online discussion
- memoir-style writing

# Release recommendation

Do not expand the regex phrase library substantially before measurement alignment work.

Freeze v0.4.1-alpha as the first operational baseline. Build v0.5 around construct alignment, input scope handling, IRR hardening, and corrected trajectory semantics.
